## 1. 背景與問題定義 / Background & Problem

### 1.1 現況

MSL 以測力板為核心提供下肢功能檢測服務。

| 面向 | 現況 |
|---|---|
| 累積資料 | 大量專業運動員檢測資料 |
| 系統計算指標 | 120+ 項生物力學指標 |
| 報告呈現指標 | 依版本約 4–12 項 |
| 報告產出時間 | 單筆 1 分鐘（原需半個工作天） |
| 版本 | Power Scan / Performance Scan / Stability Scan / Elite |
| 交付形式 | 單次、單人、PDF |

### 1.2 三個結構性問題

**P-1｜報告是快照，不是軌跡**

現行報告僅呈現單次結果。但檢測的價值在於**變化**——
訓練有沒有效、復健有沒有進展、疲勞有沒有累積，都需要跨時間比較。

目前跨時間比較的做法是人工開啟多份 PDF 並肉眼比對。
這使得「回訪」缺乏產品支撐，而回訪正是服務黏著度的來源。

**P-2｜判讀依賴專家，無法規模化**

報告輸出數值與圖表，但「這代表什麼」需要具備運動科學背景的人解讀。

現況下，具備足夠判讀能力者僅限實驗室內少數正職人員。
這形成兩個瓶頸：

- 單日可交付的深度解讀份數受限於人力
- B2B 客戶（球隊、物理治療院所）無法自行從報告得到可解釋的判讀結果

**P-3｜單人視圖無法服務機構客戶**

球隊教練關心的是「全隊 25 人誰需要優先關注」，
院所關心的是「這批復健個案的進展分佈」。

現行產品只能提供 25 份獨立 PDF，無法回答群體層級的問題。

### 1.3 問題的商業意涵

上述三點共同導致：**檢測被視為一次性服務，而非可持續訂閱的決策工具。**

這直接限制了 MSL 從成本中心轉為營收單位的可能性。

### 2.1 目標

| # | 目標 | 對應問題 |
|---|---|---|
| G-1 | 同一受測者的跨時間點比較可在報告內直接完成 | P-1 |
| G-2 | 報告自帶可解釋的判讀層，不需專家在場即可得到判讀結果（優勢與待關注項目） | P-2 |
| G-3 | 提供機構層級視圖，支援群體篩檢與排序 | P-3 |
| G-4 | 判讀層的任何輸出皆可追溯至指標與規則，可被檢測師推翻 | 全部 |

### 2.2 非目標（Non-Goals）

以下明確**不在**本版範圍，且非「延後實作」而是**刻意不做**：

| 非目標 | 理由 |
|---|---|
| **傷害預測** | 測力板量測無法支撐前瞻性傷害預測。本產品僅提供**傷害風險相關因子**之量化追蹤 |
| **醫療診斷** | 非醫療器材，不作診斷用途 |
| **以 ML 模型取代規則判讀** | 見 FR-2.4 判讀層設計決策 |
| **穿戴裝置整合** | 資料來源與效度驗證路徑不同，需獨立立項 |

> **這一節是本產品最重要的設計約束。**
> 檢測產品最常見的失敗模式是宣稱超出量測所能支撐的結論。
> 非目標清單的存在，是為了讓後續每一個功能決策都有可回推的邊界。

## 3. 使用者與使用情境 / Users & Use Cases

### 3.1 使用者分層

| 角色 | 專業背景 | 核心問題 | 目前如何被服務 |
|---|---|---|---|
| U-1 檢測師 | 運動科學 | 這份報告怎麼解讀給客戶聽 | 自行判讀 |
| U-2 教練／訓練師 | 體能訓練 | 有沒有進步、哪些指標需要關注 | 依賴 U-1 口頭說明 |
| U-3 物理治療師 | 臨床 | 患側恢復到健側的幾成 | 自行比對數值 |
| U-4 機構管理者 | 管理／採購 | 這批人誰該優先處理 | **無產品支援** |
| U-5 受測者本人 | 一般 | 我的狀況好不好、下次進步了嗎 | 收到 PDF，多半看不懂 |

### 3.2 核心使用情境

**UC-1｜訓練週期前後比較（U-2）**

教練在賽季前測一次、8 週後再測，需知道哪些指標改善、哪些退步、改變幅度是否超過量測誤差。

**UC-2｜復健進程追蹤（U-3）**

治療師每 4 週追蹤一次，需看患側／健側的對稱性隨時間收斂的軌跡。（復健進行中之個案暫不提供變化判定，僅呈現原始值與對稱性軌跡。）

**UC-3｜團隊篩檢排序（U-4）**

球隊 25 人一次檢測完畢，管理者需在一頁內看出誰的指標落在需關注區間，並據此分配有限的訓練師時間。

**UC-4｜個人回訪（U-5）**

受測者三個月後回訪，需要一份自己看得懂、能感受到變化的摘要。

## 5. 功能需求 / Functional Requirements

### 5.1 M-1 縱向追蹤（P0）

**FR-1.1 受測者身分串接**

同一受測者的多次檢測須可被系統識別為同一人，且跨版本可比。

- 跨版本比較僅限**兩版本皆產出**之指標
- 範例：Power Scan（4 指標）與 Elite（12 指標）可比較之交集為
  Jump Height、Eccentric Deceleration、Landing Peak、RFD
- 不可比之指標須明確標示「本次未測」，**不得留白或補 0**

**FR-1.2 變化量呈現**

每項指標呈現：本次值、前次值、變化量、變化率。

**FR-1.3 變化是否有意義的判定** ⭐

此為本模組的核心，也是與一般「趨勢圖」功能的根本差異。

數值變化必須先通過**量測誤差門檻**，才可被標示為「改變」。

```
判定邏輯：
  若 |本次值 − 前次值| < TE（該指標之典型誤差）
     → 標示「無顯著變化」（灰）
  若 TE ≤ |差值| < max(MDC₉₅, SWC)
     → 標示「可能有變化，但尚無法排除量測誤差，或未達實務意義」（黃）
  若 |差值| ≥ max(MDC₉₅, SWC)
     → 標示「有意義的改變」（綠／紅，依方向）

  TE  = 各指標之典型誤差（兩次量測差值之標準差 ÷ √2，由驗證研究估計）
  MDC₉₅ = 2.77 × TE（兩次量測之差值在 95% 信心下可與雜訊區分之最小值）
  SWC = 0.2 × 該族群之受試者間標準差（最小有意義變化）
```

> **註：** 兩次量測之差值本身含約 √2 × TE 之雜訊，故綠／紅須同時超過 MDC₉₅ 與 SWC。
> TE / SWC 比值 > 1.2 之指標不提供變化判定，僅呈現原始值；比值 0.8–1.2 之「邊際」指標提供判定並標示「邊際」
> （見驗證計畫書 §8.6）。

> **為什麼這條是 P0 而非 P2：**
> 不做這件事，縱向追蹤會把雜訊報告成進步或退步。
> 一個會說「你進步了 3%」但那 3% 落在誤差內的產品，
> 比沒有追蹤功能更糟——它會侵蝕客戶對整套檢測的信任。

**FR-1.4 TE 與 SWC 的來源與更新**

- 首版參數來自驗證計畫書（MSL-VP-REL-2026-001）之前瞻性重複量測研究；歷史重複檢測資料僅用於設計決策，不進入最終參數
- 依族群分層（競技／一般健身／復健後期）分別估計；復健進行中之個案不在驗證母群內，不適用變化判定
- 累積足夠之標準化重複檢測資料（每層 n ≥ 50）後重新估計，版本化留存
- 樣本數不足以估計 TE 之指標（含驗證研究未涵蓋之動作，如 SJ、DJ、側向跳、星形平衡），**該指標不提供變化判定**，僅呈現原始值

### 5.2 M-2 規則式判讀層（P0）

**FR-2.1 判讀輸出三層結構**

每份報告產出：

| 層 | 內容 | 數量上限 |
|---|---|---|
| 表現優勢 | 高於族群基準且具實務意義者 | 1–2 項 |
| 待關注項目 | 低於基準且為該運動關鍵能力者 | 1–2 項 |
| 關注旗標 | 觸發絕對閾值或對稱性閾值者 | 不限 |

各層無符合項目時顯示「無」，不以較低優先之項目補足。「族群基準」之定義與來源於規則表定稿時明訂。

**FR-2.2 旗標觸發規則（明文、可稽核）**

| 規則 | 條件 | 旗標 |
|---|---|---|
| R-1 | Landing Peak 高於設定閾值 | 🔴 著地負荷偏高 |
| R-2 | Asymmetry Index 高於上限閾值 | 🔴 對稱性風險相關因子 |
| R-3 | Asymmetry Index 介於警示閾值與上限閾值之間 | ⚠️ 對稱性監控 |
| R-4 | SCMJ Landing Peak 高於 CMJ Landing Peak（比較前須確認兩者為同一標準化基準） | ⚠️ 單腳著地策略偏硬 |
| R-5 | Landing Peak 高 **且** Eccentric Deceleration 低（高／低之閾值於規則表定稿時明訂） | 🔴 著地僵硬 + 煞車不足 |
| R-6 | Dynamic Stability 左右差高於設定值 | ⚠️ 單側控制差異 |
| R-7 | 閉眼單腳站未達標準時長 | ⚠️ 平衡低於一般水準 |
| R-8 | Sway Velocity 高於設定值 | ⚠️ 晃動偏高 |

> **註：** 具體閾值屬實驗室內部規則表，本文件不列出；所有閾值於首版皆為**暫定值**，
> 須與文獻及族群資料對照，並於 P2 由檢測師逐條審查後定稿。

**FR-2.3 運動情境加權**

旗標之優先排序依受測者主項目調整，對照表如下（示意節錄，非實際加權設定）：

| 運動 | 首要指標 | 次要指標 |
|---|---|---|
| 籃球 | Jump Height AI + Dynamic Stability | Landing Peak |
| 羽球 | Dynamic Stability + RFD AI | Jump Height AI |
| 馬拉松／越野跑 | Eccentric Deceleration + Landing Peak | Asymmetry |
| 滑雪 | Eccentric Deceleration + Dynamic Stability | Balance |
| 攀岩 | Dynamic Stability (SCMJ) + Balance | Landing Peak |
| 一般健身 | Jump Height + Eccentric Deceleration | RFD |

**FR-2.4 設計決策：規則式，不用機器學習** ⭐

| | 規則式 | ML 模型 |
|---|---|---|
| 可解釋性 | 每個結論可回推至具體閾值 | 需額外解釋機制 |
| 可推翻性 | 檢測師可指出規則不適用 | 難以針對個案推翻 |
| 宣稱邊界 | 規則本身即為邊界，不會外推 | 可能學到不該宣稱的關聯 |
| 稽核 | 規則表即稽核文件 | 需模型版本與訓練資料管理 |
| 冷啟動 | 立即可用 | 需標註資料 |

**選擇規則式。** 本產品的核心價值是**可信**而非**聰明**。
一個能被專業人員檢查並推翻的判讀層，比一個準確率更高但不可解釋的模型更適合此情境。

當規則式判讀累積足夠的「檢測師推翻紀錄」後，再評估是否以該資料訓練模型——
屆時推翻紀錄即為標註資料。

**FR-2.5 判讀層的措辭約束**

判讀文字產出須通過以下檢查（自動化）：

- 禁用詞：傷害預測、預防傷害、臨床證實、診斷
- 「傷害風險」一律寫為「傷害風險**相關因子**」
- 不得以相關性陳述因果（禁用句型：「因為 X 低，所以會 Y」）
- 「減速能力」與「穩定性」不得互換使用
- 每則判讀結論須標示其依據之指標與規則編號

### 5.3 M-3 機構儀表板（P1）

**FR-3.2 分佈視圖**

**FR-3.3 批次匯出**

**FR-3.4 權限**

### 5.4 M-4 受測者簡版報告（P1）

**FR-4.1 一頁式**

三個重點：與上次比較的變化、一項優勢、一項待關注指標。

**FR-4.2 語言層級**

不使用 N·s⁻¹、N/BW、COP 等單位；改以相對描述與圖示。

**FR-4.3 與完整報告一致**

簡版之結論必須由完整報告之同一規則產生，不得另立邏輯。

### 5.5 M-5 資料匯出 API（P2）

**FR-5.1 端點**

- `GET /subjects/{id}/assessments` — 該受測者所有檢測
- `GET /assessments/{id}` — 單次檢測完整指標（含未呈現於報告之 120+ 項）
- `GET /organizations/{id}/summary` — 機構層級彙總

**FR-5.2 認證**

機構層級 API key，範圍限該機構資料。

**FR-5.3 資料契約**

回傳含指標值、單位、方向（higher/lower is better）、TE、SWC、所屬版本，
使第三方系統無需理解 MSL 內部邏輯即可正確呈現。

## 6. 指標選擇邏輯 / Metric Selection

系統計算 120+ 項指標，報告呈現 4–12 項。**此比例為刻意設計，非技術限制。**

### 6.1 呈現原則

| 原則 | 說明 |
|---|---|
| 可解讀 | 該指標的高低具明確的臨床或表現意義 |
| 可解釋 | 檢測師能在 30 秒內向非專業者說明其意義 |
| 可追蹤 | 該指標的再測信度足以支撐跨時間比較（TE 已知） |
| 不重複 | 與已呈現指標高度相關者擇一 |

**未通過上述四項者，計算但不呈現**，保留於資料庫供研究與 API 調用。

### 6.2 為何不「全部給客戶」

給出 120 項指標會產生三個後果：

1. 使用者無法判斷該看哪一項，實質等於沒有資訊
2. 指標間彼此相關，同一現象被重複計數，放大主觀印象
3. 在 120 項中必然有數項落在極端，誘發對雜訊的過度解讀

**決定不呈現什麼，和決定呈現什麼同等重要。**

## 9. 風險與緩解 / Risks & Mitigation

| # | 風險 | 影響 | 可能性 | 緩解 |
|---|---|---|---|---|
| RS-1 | 驗證研究樣本不足以精確估計部分指標之 TE | 該指標無法提供變化判定 | 中 | 分層估計；不足者僅呈現原始值並明示 |
| RS-2 | 判讀層產生專業上不恰當之結論 | 專業信譽損害 | 中 | 措辭檢查 + 發布前由檢測師逐條審查規則表 + 推翻機制 |
| RS-3 | 機構客戶要求「誰會受傷」的預測功能 | 商業壓力導致越線 | **高** | 非目標清單納入合約與售前說明；提供「風險相關因子排序」作為替代 |
| RS-4 | 跨版本比較被誤用（以 Power Scan 比 Elite） | 錯誤結論 | 中 | 系統僅允許交集指標比較，其餘明示「本次未測」 |
| RS-5 | 規則式判讀被視為「不夠 AI」 | 市場定位質疑 | 中 | 以可稽核性與可推翻性作為賣點；保留後續模型化路徑 |
| RS-6 | 開發資源不足（實驗室人力有限，無專職工程） | 時程延誤 | **高** | P0 範圍刻意限縮於既有量測之上；M-3 以後外包或延後 |
| RS-7 | 驗證研究顯示沒有任何指標滿足 TE < SWC（依驗證計畫書 §2.3 推導，需 ICC > 0.96，屬預期中的可能結果） | M-1 個人層級變化判定無法交付 | **高** | 於 P1 結束設決策點 DP-1（見 §10）：依結果縮限 M-1 範圍或延後；不降低門檻 |

> **RS-3 是本產品最需要防守的風險。** 它的可能性高、影響大，
> 而且壓力來自付錢的一方。非目標清單必須在售前階段就出現，
> 不能等到客戶簽約後才說「這個我們不做」。

## 附錄 B：對稱性判定 / Asymmetry

```
AI (%) = |Strong − Weak| / (Strong + Weak) × 100
Symmetry % = 100 − AI
```

Strong／Weak 依該指標之好壞方向定義。
對 Landing Peak、Dynamic Stability、Sway Velocity 等 Lower is better 之指標，
文字解讀須標示高值側為「負荷側／晃動側」，**不得稱為強側**。

| AI | 旗標 | 後續處理 |
|---|---|---|
| 低於警示閾值 | ✅ 正常 | 維持 |
| 介於警示與上限閾值 | ⚠️ 監控 | 持續追蹤 |
| 高於上限閾值 | 🔴 風險相關因子 | 建議由檢測師複查 |

> 本公式之分母為兩側總和，與文獻常見之定義（以平均或強側為分母）不同，
> 閾值不可直接與文獻數值對照；具體閾值為暫定值，不在本文件列出。
