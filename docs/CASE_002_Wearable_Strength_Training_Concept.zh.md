# CASE-002 | 穿戴式阻力訓練智慧

**分類：** 虛構的獨立概念。不是已上市產品、客戶合作、已部署系統、已完成測試，或經驗證的臨床／技術結果。

## 一個範圍明確的 V1 問題

腕戴式 IMU 能否協助使用者回顧一小組預先選定的上肢阻力訓練的次數與節奏，同時不要求感測器推論超出其可觀察範圍的內容？

本案例刻意把答案收窄：針對三項擬支援的動作，提供次數、階段時間、信心指示與人工修正。不承諾動作品質評分、傷害風險預測、診斷或自動負荷處方。

## 每項主張的分類

| 類型 | 本案例中的內容 |
| --- | --- |
| **Target（目標）** | 三項支援動作；針對事件精確度、召回率、次數誤差、時間、延遲與信心校準所擬定的發布門檻。 |
| **Assumption（假設）** | 一般腕戴裝置能提供可用的 IMU 訊號；以狀態為基礎的取樣設計可管理耗電；使用者可在組後摘要中修正明顯的錯誤。 |
| **Evidence Needed（待補證據）** | 目標硬體的功耗與溫升表現、與參考標記的一致性、受試者獨立的表現、最差切片的表現、BLE 可靠度，以及使用者對信心指示的理解。 |
| **Not claimed（不主張）** | 產品部署、客戶使用、已完成的資料蒐集、模型表現、已達成的指標、臨床驗證、診斷能力、傷害預測，或全身動作品質評分。 |

## 產品決策

擬議的 V1 從預先選定的動作開始，而不是通用的動作辨識。使用者選擇一項支援的動作、完成一組，取得暫定的次數與節奏摘要，並可在信心偏低時自行修正。

```text
預先選定的支援動作
        ↓
IMU 事件視窗與階段推論
        ↓
信心門檻
        ├── 信心足夠 → 暫定事件摘要
        ├── 信心偏低 → 需要複核
        └── 不支援的動作 → Unknown 或手動記錄
```

`Unknown` 是有效的結果。系統不應默默猜測成另一項動作，也不應把低信心事件變成安全結論。

## 擬議範圍

| 納入擬議的 V1 | 不納入擬議的 V1 |
| --- | --- |
| 三項選定的上肢阻力動作 | 下肢動作與廣泛的動作庫 |
| 次數、階段時間、組內節奏一致性 | 個人化教練與自動負荷處方 |
| 信心指示與人工修正 | 多裝置感測與持續依賴原始訊號串流 |
| 對未知或不支援動作的明確備援 | 診斷、傷害預測或姿勢安全評分 |

## 擴充前的驗證

擬議的發布決策依據整體表現**以及**每個預先定義的最差切片，而不只看對自己有利的平均值。證據計畫需以受試者獨立的評估資料，測試動作、相對負荷、節奏、配戴手側、疲勞、貼合度與背景動作。

若任一預先定義的切片未達其擬議門檻，下一步是縮小範圍、改善備援，或回到證據蒐集，而不是擴大承諾。

## 這個案例展示什麼

- 感測器可觀察性有限時的範圍控制。
- 讓信心與未知狀態可見的產品契約。
- 區分提案與結果的驗證門檻。
- 把與安全相關的過度宣稱視為產品風險的上線設計。
